# Марко Петкович — "WatchDemo"
# Пользовательские сценарии

### Группа: 11 - И - 4

Ниже приведены пользовательские сценарии, соответствующие функциональным требованиям первоначальной заявки WatchDemo.

### [ Сценарий 1 — Работа с аккаунтом ]

1. Пользователь выбирает действие регистрации или входа в существующий аккаунт.
2. Пользователь вводит адрес электронной почты и пароль либо данные для создания нового аккаунта.
3. Система проверяет корректность введённых данных и сообщает пользователю об ошибке, если данные имеют неверный формат.
4. Система создаёт новый аккаунт либо авторизует пользователя, если введённые данные корректны.
5. Пользователь запрашивает восстановление пароля, если не может войти в аккаунт.
6. Система отправляет пользователю инструкцию для восстановления пароля и принимает новый пароль после подтверждения.
7. Пользователь открывает настройки профиля и изменяет доступные данные аккаунта.
8. Система сохраняет изменения профиля и сообщает пользователю об успешном обновлении данных.
9. Система открывает пользователю доступ к сохранённым матчам и отчётам после успешной авторизации.

### [ Сценарий 2 — Загрузка demo-файла ]

1. Пользователь выбирает функцию загрузки нового demo-файла.
2. Система открывает область выбора файла и сообщает пользователю поддерживаемый формат .dem.
3. Пользователь выбирает demo-файл Counter-Strike 2 на своём устройстве.
4. Система принимает файл и отображает пользователю состояние загрузки.
5. Система завершает загрузку файла и ставит его в очередь на обработку.
6. Система сообщает пользователю, что demo-файл принят и начинается анализ матча.
7. Пользователь ожидает завершения обработки, наблюдая текущий статус.
8. Система переводит пользователя к результатам обработки после успешного завершения анализа.

### [ Сценарий 3 — Проверка загруженного demo-файла ]

1. Система получает загруженный пользователем файл перед началом полного анализа.
2. Система проверяет расширение файла и возможность прочитать его как demo Counter-Strike 2.
3. Система проверяет наличие данных, необходимых для дальнейшего анализа матча.
4. Система прекращает обработку, если файл повреждён, имеет неподдерживаемый формат или не содержит необходимых данных.
5. Система сообщает пользователю причину, по которой файл не удалось обработать.
6. Пользователь выбирает другой demo-файл после сообщения об ошибке.
7. Система повторно проверяет новый файл и запускает обработку, если проверка завершилась успешно.

### [ Сценарий 4 — Извлечение данных из demo-файла ]

1. Система открывает прошедший проверку demo-файл и начинает его разбор.
2. Система определяет участников матча и команды игроков.
3. Система определяет границы раундов, их результаты и изменение счёта.
4. Система извлекает убийства, смерти и другие необходимые игровые события.
5. Система извлекает позиции игроков и необходимые данные об их перемещениях по времени.
6. Система извлекает данные о бомбе, гранатах и других событиях, используемых в отчёте.
7. Система прекращает обработку конкретного блока данных и фиксирует ошибку, если часть demo невозможно корректно прочитать.
8. Система сохраняет успешно извлечённые данные в структуре, пригодной для дальнейшего расчёта статистики, радара и анализа.

### [ Сценарий 5 — Выбор игрока для персонального анализа ]

1. Система выводит список игроков, найденных в обработанном demo-файле.
2. Пользователь просматривает список игроков и выбирает игрока для персонального анализа.
3. Система выделяет выбранного игрока и предлагает подтвердить выбор.
4. Пользователь подтверждает выбранного игрока.
5. Система запускает формирование персонального отчёта для выбранного игрока.
6. Пользователь возвращается к списку игроков, если хочет изменить выбор.
7. Система отменяет предыдущий выбор и позволяет выбрать другого игрока.
8. Система открывает сформированный персональный отчёт после завершения расчётов.

### [ Сценарий 6 — Просмотр статистики игрока ]

1. Система рассчитывает основные статистические показатели выбранного игрока после обработки матча.
2. Система выводит количество убийств, смертей и отношение K/D.
3. Система выводит ADR и другие показатели, используемые в текущей версии анализа.
4. Система выводит показатели первых убийств и первых смертей игрока.
5. Система выводит дополнительные показатели, связанные с разменами и результатами раундов, если для них достаточно данных.
6. Пользователь просматривает статистику и выбирает интересующий показатель.
7. Система показывает значение выбранного показателя в контексте конкретного матча.
8. Система помечает показатель как недоступный, если demo-файл не содержит данных, необходимых для его корректного расчёта.

### [ Сценарий 7 — Просмотр матча на интерактивном 2D-радаре ]

1. Пользователь открывает вкладку интерактивного радара из отчёта по матчу.
2. Система отображает карту и позиции игроков для выбранного момента матча.
3. Система отображает принадлежность игроков к сторонам CT и T и их состояние alive/dead.
4. Пользователь запускает или приостанавливает воспроизведение матча на радаре.
5. Система обновляет позиции игроков и ключевые состояния при изменении времени воспроизведения.
6. Пользователь выбирает другой момент матча с помощью элементов управления воспроизведением.
7. Система перемещает состояние радара к выбранному моменту.
8. Система сообщает о невозможности отобразить радар, если для выбранной карты отсутствует необходимая конфигурация.

### [ Сценарий 8 — Работа с временной шкалой матча ]

1. Пользователь открывает временную шкалу в отчёте или на странице радара.
2. Система разделяет временную шкалу на раунды и доступные игровые фазы.
3. Система отображает на шкале ключевые события матча, для которых доступно точное время.
4. Пользователь выбирает нужный раунд на временной шкале.
5. Система перемещает отчёт и радар к началу выбранного раунда.
6. Пользователь выбирает отдельное событие или момент внутри раунда.
7. Система переводит воспроизведение к ближайшему доступному состоянию demo для выбранного момента.
8. Система сообщает пользователю, если для события отсутствуют данные, позволяющие выполнить точный переход.

### [ Сценарий 9 — Автоматический поиск игровых проблем ]

1. Система получает данные выбранного игрока и контекст матча после завершения основного парсинга.
2. Система разделяет действия и перемещения игрока на анализируемые игровые эпизоды.
3. Система определяет информацию о противниках, которая была доступна игроку в соответствующие моменты матча.
4. Система учитывает возможные области нахождения противников и маршрут движения выбранного игрока.
5. Система применяет реализованные правила обнаружения игровых проблем к подходящим игровым эпизодам.
6. Система отклоняет ситуацию, если имеющихся данных недостаточно для обоснованного вывода.
7. Система сохраняет ситуацию как найденную проблему, если условия конкретного правила выполнены и контекст подтверждает вывод.
8. Система передаёт найденные проблемы в модуль формирования персонального отчёта.

### [ Сценарий 10 — Формирование списка наиболее значимых проблем ]

1. Система получает все игровые проблемы, найденные для выбранного игрока в матче.
2. Система группирует найденные ситуации по типам игровых проблем.
3. Система оценивает доступные признаки значимости каждой найденной ситуации.
4. Система исключает дублирующиеся или недостаточно подтверждённые ситуации.
5. Система формирует ограниченный список наиболее значимых проблем игрока в этом матче.
6. Пользователь открывает раздел с основными проблемами в персональном отчёте.
7. Система показывает пользователю тип каждой проблемы и краткую информацию о соответствующей ситуации.
8. Система сообщает пользователю, если в матче не найдено достаточного количества подтверждённых проблем.

### [ Сценарий 11 — Переход от найденной проблемы к игровому моменту ]

1. Пользователь выбирает найденную проблему в персональном отчёте.
2. Система открывает карточку проблемы и показывает раунд, время и краткое объяснение.
3. Система показывает данные игрового контекста, которые используются для обоснования найденной ситуации.
4. Пользователь выбирает действие перехода к моменту матча.
5. Система определяет ближайший доступный момент воспроизведения для найденной ситуации.
6. Система открывает интерактивный радар на соответствующем раунде и времени.
7. Пользователь воспроизводит ситуацию на радаре и самостоятельно проверяет вывод системы.
8. Система сообщает пользователю, если точный переход невозможен из-за отсутствующих данных, и переводит его к ближайшему доступному моменту.

### [ Сценарий 12 — Сохранение и повторное открытие результата анализа ]

1. Система связывает успешно обработанный матч и сформированный отчёт с аккаунтом авторизованного пользователя.
2. Система сохраняет в базе данных метаданные матча и данные, необходимые для повторного открытия отчёта.
3. Пользователь открывает раздел ранее обработанных матчей после входа в аккаунт.
4. Система загружает список сохранённых матчей пользователя с сервера.
5. Пользователь выбирает ранее обработанный матч.
6. Система загружает сохранённый отчёт и связанные с ним данные анализа.
7. Система сообщает пользователю об ошибке, если сохранённый результат недоступен или был повреждён.
8. Пользователь открывает статистику, найденные проблемы и доступные элементы повторного просмотра без повторной загрузки demo-файла.

### [ Сценарий 13 — Экспорт результатов анализа в JSON ]

1. Пользователь открывает ранее сформированный персональный отчёт по матчу.
2. Пользователь выбирает функцию экспорта основных результатов анализа.
3. Система формирует JSON-файл с основными метаданными матча, статистикой выбранного игрока и найденными проблемами.
4. Система проверяет, что экспортируемые данные относятся к текущему отчёту и доступны для выгрузки.
5. Система сообщает пользователю об ошибке, если сформировать файл невозможно из-за отсутствующих данных.
6. Система предлагает пользователю сохранить сформированный JSON-файл после успешной подготовки.
7. Пользователь сохраняет файл на своём устройстве.
8. Система завершает экспорт, не изменяя сохранённый в сервисе отчёт.
