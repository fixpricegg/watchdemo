# Марко Петкович — WatchDemo

### Группа: 11И4

## Название проекта

WatchDemo

## Проблемное поле

Для роста в соревновательных играх игрокам необходимо анализировать свои матчи и находить повторяющиеся ошибки. В Counter-Strike 2 полноценный самостоятельный разбор матча требует загрузки demo-файла, работы со встроенным просмотрщиком и ручного поиска важных игровых ситуаций. Это занимает значительное время и требует от игрока понимания того, на какие моменты следует обращать внимание. Услуги тренера также доступны не всем.

Проблема проекта заключается в отсутствии простого инструмента, который объединяет автоматическую обработку demo-файла, основные показатели игрока, обнаружение ограниченного набора игровых проблем и быстрый переход к конкретным моментам матча для их проверки.

## Заказчик / потенциальная аудитория

Основная целевая аудитория WatchDemo — игроки Counter-Strike 2 примерно 14–30 лет, регулярно играющие в соревновательном режиме или на платформе FACEIT и заинтересованные в повышении своего игрового уровня. На первом этапе продукт ориентирован преимущественно на русскоязычных пользователей из России и стран СНГ.

Основной сегмент — любители и полупрофессиональные игроки среднего и высокого уровня, которые уже понимают основные механики CS2, но не имеют постоянного тренера или не хотят тратить значительное количество времени на самостоятельный просмотр demo-файлов. Дополнительным сегментом могут быть небольшие команды и более опытные игроки, которым нужен быстрый способ просмотра игровых ситуаций и поиска повторяющихся ошибок.

Пол пользователя не является значимым критерием сегментации.

## Аппаратные / программные требования

- персональный компьютер с современным браузером;
- подключение к интернету для работы с веб-приложением;
- demo-файл матча Counter-Strike 2 формата `.dem`;
- серверная часть приложения должна иметь возможность временно принять и обработать загруженный demo-файл;
- основная пользовательская платформа — Web; отдельное Desktop-приложение в рамках ИВР не разрабатывается.

## Функциональные требования

Итоговый продукт представляет собой веб-приложение. Основной пользовательский сценарий: загрузка demo-файла → автоматическая обработка матча → выбор игрока → просмотр результатов анализа → переход к конкретным игровым ситуациям.

1. Загрузка demo-файла Counter-Strike 2 формата `.dem`.
2. Проверка загруженного файла и обработка корректной записи матча.
3. Получение из demo-файла информации об игроках, раундах и основных игровых событиях.
4. Выбор игрока, для которого проводится персональный анализ.
5. Расчёт основных игровых статистических показателей выбранного игрока.
6. Отображение интерактивного радара карты с позициями игроков.
7. Воспроизведение хода матча на радаре с отображением ключевых игровых объектов и событий.
8. Отображение временной шкалы матча с возможностью перехода к выбранному моменту.
9. Автоматическое обнаружение нескольких типов игровых ошибок или проблем на основе данных demo-файла.
10. Формирование списка наиболее значимых обнаруженных проблем игрока.
11. Привязка обнаруженной проблемы к конкретному раунду и моменту матча.
12. Возможность перейти из результата анализа непосредственно к соответствующему моменту на интерактивном радаре.
13. Формирование итоговой страницы отчёта, объединяющей статистику, обнаруженные проблемы и средства просмотра игровых ситуаций.

Интерфейс должен быть понятен пользователю, знакомому с Counter-Strike 2, без необходимости самостоятельно работать с demo-файлом через внутриигровой просмотрщик.

## Похожие / аналогичные продукты

К аналогам относятся сервисы анализа матчей Counter-Strike 2 и инструменты просмотра demo-файлов, например Leetify, Scope.gg и CS Demo Manager. Они подтверждают востребованность статистики и разбора сыгранных матчей. WatchDemo в рамках ИВР делает акцент на едином пользовательском сценарии: автоматическая обработка `.dem`, ограниченный набор автоматически обнаруживаемых проблем и связь каждого вывода с конкретным моментом на интерактивном радаре.

## Инструменты разработки, информация о БД

- Python — основная серверная логика и обработка данных;
- `demoparser2` — извлечение данных из demo-файлов Counter-Strike 2;
- FastAPI — backend/API веб-приложения;
- React — frontend и интерактивный интерфейс;
- JSON — передача и хранение результатов обработки матча между компонентами приложения;
- Git и GitHub — контроль версий и хранение исходного кода.

На текущем этапе ИВР постоянная база данных не является обязательной частью минимальной версии продукта: анализ строится вокруг загруженного demo-файла и сформированного отчёта. Авторизация, пользовательские профили, история матчей, платежи и связанные с ними постоянные данные относятся к возможному дальнейшему развитию проекта после ИВР.

## Возможные риски

- **Различия и пограничные случаи в demo-файлах.** Решение: тестирование на нескольких матчах и обработка некорректных или отсутствующих данных.
- **Слишком высокая сложность автоматического определения игровых ошибок.** Решение: ограничить количество анализируемых типов проблем и добавлять только те правила, которые можно проверить по данным demo-файла.
- **Ложные срабатывания алгоритмов анализа.** Решение: ручная проверка найденных ситуаций на реальных demo-файлах и корректировка критериев.
- **Недостаток времени до защиты.** Решение: зафиксировать минимальный набор функций и отложить авторизацию, профили, платежи, интеграцию с игровыми платформами и другие второстепенные возможности до завершения ИВР.
- **Низкая полезность отдельных метрик для пользователей.** Решение: провести пользовательское тестирование с игроками Counter-Strike 2 и скорректировать анализ по результатам обратной связи.
- **Технические сбои приложения.** Решение: регулярное тестирование, контроль версий через GitHub и резервное хранение исходного кода.
