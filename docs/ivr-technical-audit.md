## Реализованное изменение

ADR добавлен в отдельный `backend/adr.py`; интеграция в существующий анализатор
только аддитивная: чтение player_hurt и pre-hit health, вызов расчёта, новые поля
`stats.adr`, `stats.adr_details`, `report.summary.adr`, `report.adr_details`.
Прежние поля, radar, события, библиотеки, детекторы и Decision Context сохранены.
Markdown-отчёт и Summary показывают ADR, старые сохранённые отчёты показывают N/A.
Автоматического изменения старых результатов нет: ADR появляется в новых анализах.

**Формула:** фактический урон здоровью противников / число наблюдаемых завершённых
раундов с участием выбранного SteamID. В числителе player_hurt.dmg_health,
ограниченный здоровьем жертвы перед попаданием; dmg_armor не используется.
В реальной demo dmg_health бывает больше остатка HP (например, 110 при смертельном
выстреле), поэтому простое суммирование даёт overkill. Здоровье читается на tick-1,
а для нескольких событий по одной жертве в одном tick применяется здоровье после
предыдущего события в исходном стабильном порядке. Совпадающие hits автоматически
не дедуплицируются: это может быть настоящий многократный урон.

Учитываются event-time стороны 2/3, включая смену сторон; исключены self/team,
world, C4/planted_c4, броня, разминка/события вне live-интервалов и после первого
round_end с победителем CT/T. Knife и атрибутированный урон гранат/огня по врагу
в live-раунде учитываются, в том числе после смерти атакующего.

Знаменатель не зависит от числа убийств или попаданий: раунды без урона считаются.
Участие подтверждается tick-состоянием SteamID на T/CT до round_end. Позднее
подключение не приписывает игроку предыдущие раунды. Это метрика наблюдаемого
участия в записи: отсутствующие части demo и состояние подключения за пределами
записи не восстанавливаются. Незавершённые раунды, неизвестные стороны/здоровье
или отсутствие обязательных колонок дают partial/unavailable и ADR=null,
а не выдуманный ноль. known_damage при partial — только известная часть.
Идентификатор игрока берётся из уникального player_info, не из сравнения названий
команд или итогового scoreboard. Неоднозначный одинаковый nickname даёт ADR N/A.

**Экспорт:** `GET /reports/{uuid}/export` проверяет сессию и владельца через тот же
SQL-фильтр, что чтение отчёта. Гость получает 401, чужой/отсутствующий UUID — 404,
неуспешный/незавершённый анализ — 409. Возвращает attachment JSON с report/match ID,
временем создания, именем игрока, картой, основными числовыми показателями и Top
Problems. Это компактный экспорт отчёта, не огромный replay snapshot.
Фиксированный whitelist полей и типов не переносит DB-строки, stats целиком,
пароли, токены, email аккаунта, пути к файлам, SQL-конфигурацию или внутренние data.
Cache-Control=no-store и Content-Disposition формируются сервером.
В SavedReportPage добавлена обычная ссылка «Скачать отчёт JSON», без редизайна.

Top Problems явно подписаны как статистические сигналы для проверки. Отсутствие
сигналов не выдаётся за отсутствие ошибок. Детекторы не переписывались и не
переобъявлялись подтверждённой аналитикой игровых решений.

## Проверки и доказательства

- Backend: 277 тестов, 0 пропусков, 0 падений (263 прежних + 11 ADR + 3 export).
  PostgreSQL 17.6 настоящий, схемы watchdemo_test_UUID; рабочая manual DB не трогалась.
- ADR fixtures: overkill, нулевые раунды, стороны после halftime, utility после
  смерти, self/team/world/C4, post-round/warmup, несколько hits за tick, late join,
  отсутствующие поля и незавершённая запись.
- Export: разрешённый download, старый формат без ADR, запрет A/B/гостей,
  failed/missing, whitelist включая попытки передать вложенный token в summary/advice.
- Прежние тесты загрузки проверяют расширение, невалидную demo, размер (<, =, >),
  413/cleanup/отсутствие INSERT, выбор/ошибку игрока, PostgreSQL failures, сессии,
  CSRF, пароли, историю, новые приложения и реальные процессы Uvicorn.

  не объявляется чистым: прежние ошибки Radar/UploadPage не относятся к задаче.
- Chrome: вход, ADR 42.5 на синтетическом сохранённом отчёте, настоящий JSON download
  с проверкой содержимого, refresh, профиль/logout/регистрация B и отказ B по URL;

  удаление временной копии → новый app и два отдельных процесса Uvicorn с остановкой
