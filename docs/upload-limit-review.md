# Повторное ревью загрузки demo

База: `542221a`, ветка `feature/postgres-match-storage`. Изменение отдельным
локальным коммитом, без merge/push. Пользовательский `codex-review.diff` сохранён.

## Изменения

`WATCHDEMO_MAX_DEMO_BYTES` — максимальный размер содержимого `.dem` в байтах,
по умолчанию 1073741824 (1 GiB). Положительное целое считывается при создании
приложения; некорректная конфигурация запрещает запуск вместо отключения лимита.
Пример локальной настройки до запуска Uvicorn:

```powershell
$env:WATCHDEMO_MAX_DEMO_BYTES = '536870912' # 512 MiB
```

Копирование считает фактически прочитанные байты блоками не больше 1 MiB.
Не используется доверие к Content-Length или размеру, объявленному клиентом.
На точной границе выполняется чтение одного проверочного байта. При превышении
возвращается 413 с размером лимита, частичный UUID-файл удаляется существующим
обработчиком очистки. Парсер и INSERT матча до окончания проверки не вызываются.
Чужие файлы в upload-каталоге не удаляются. Точный лимит допустим.

Лимит относится к `.dem` на этапе копирования из UploadFile. FastAPI предварительно
спулирует multipart на временный диск; ограничение всего HTTP-запроса/его скорости
для публичного размещения следует задавать также на reverse proxy. Изменение
не объявляется защитой от всех способов исчерпания HTTP-ресурсов.

Дополнительно исправлено сравнение CSRF-токенов: недопустимые не-ASCII байты
заголовка больше не вызывают TypeError/500, а отклоняются с 403. Сессии, cookie,
сроки действия и контракты аккаунтов не менялись. Новых зависимостей и миграций нет.

## Проверки

- Полный backend unittest: **263 пройдено, 0 пропущено, 0 упало** на реальном
  изолированном PostgreSQL 17.6 (финальный прогон 61.300 с). Из них 7 новых тестов лимита (4 unit и 3 PostgreSQL)
  и 2 новых негативных теста аккаунтов. Прежние 254 теста также проходят.
- Превышение после частичной записи: 413, файла нет, парсер/сохранение не вызваны,
  SQL count(matches)=0; существующий файл сохранён.
- Точный и меньший размеры: вход сохранён полностью, запись имеет правильного владельца.
- Проверены ограниченные чтения и остановка на первом лишнем байте без дочитывания
  остатка; проверена положительная конфигурация и ошибки конфигурации.
- Повторно проверены регистрация, вход, изоляция A/B, прямые UUID и повторный анализ,
  отзыв сессий, смена/сброс пароля и почта через loopback SMTP.
- Без CSRF, пустой/чужой/не-ASCII CSRF и недопустимый Origin: 403 без изменения данных.
  Гость даже с валидным anonymous CSRF не может загрузить demo (401).
- `npm run build`: успешно. React и компоненты радара не менялись.
- `git diff --check`: успешно. Анализатор, detectors, library, geometry, context,
  radar, frontend и SQL-миграции отсутствуют в diff относительно `542221a`.

Реальный сценарий запускается воспроизводимым
`backend/scripts/qa_real_demo_accounts.py`: регистрация/вход → загрузка и анализ
`match19nuke.dem` → сохранение → удаление временной копии → новое приложение и
два последовательных независимых процесса Uvicorn с остановкой между ними →
повторный вход и сравнение полного результата. Исходная demo только читается,
её SHA-256 проверяется до/после. Каждый запуск использует отдельную тестовую
схему, реальные рабочие данные не обновляются. Результат реального прогона и SHA
сохранены в `review-upload-limit/real-demo.log`.
Фактический повторный прогон успешен: `wesiqe`, 22 раунда, обе отметки
`REAL_PROCESS_REOPEN_OK` и `REAL_DEMO_OK`. SHA-256 исходника до/после:
`59c05c5e8927b877cb69620aa002416f9690e3c44c009dcad6743367833036ac`.
SHA-256 полного нормализованного результата:
`33e7a8dc38d58f9946b0e0d53055a89868739fcd02c37586a024e9b42216e96c`.
После завершения проверено отсутствие оставшихся тестовых схем.

Логи и patch находятся в `review-upload-limit/` и не включаются в Git:
`backend-tests.log`, `frontend-build.log`, `real-demo.log`, `upload-limit.patch`.
Вход для ИВР остаётся обязательным, гостевой режим не добавлен.
