# Проверка интеграционной версии ИВР

Папка `WatchDemo-ivr`, ветка `integration/ivr-2026-11-05`, исходная база `3ef871a`.
Существовавшие изменения сохранены отдельным коммитом `1c8e74d` перед исправлениями.
Другие worktree не редактировались. Публикация и merge в основную ветку не выполнялись.

## Что изменено

- Entry Death отбирает первую смерть от противника по событиям и event-time сторонам.
  Teamkill, suicide и world не превращаются в opening-ошибки. Исход размена указан
  как послематчевый факт; неполное окно остаётся неизвестным.
- Missed Trade v2 сохраняет проверки жизни, свежести позиций, команд, полного окна,
  навигации, поддержки до смерти, стрельбы/урона, ограничений игрока и дыма.
  Окно теперь ограничено настоящим round_end, а мгновенный размен в том же тике
  исключает кандидата. Кандидат не доказывает доступность выстрела или ошибку.
- Buy Mismatch сохраняет исходные пороги: три союзника от $3000, игрок до $1200
  и остаток от $3000. Требуются живые игроки с уникальными ID и снимками точного
  первого live-тика. Пропуски, stale/future и нечисловые значения не заменяются нулями.
- `report.review_findings`, `top_problems`, события и Markdown используют единый
  контракт. Приоритет задаёт порядок ручного просмотра; старые агрегатные эвристики
  вынесены в `statistical_signals`. Формулировка «провальный entry» по одной смерти
  удалена. JSON-экспорт проецирует только публичные поля эпизодов.
- Вместо заглушек появился список карточек: факты, ограничения, фильтрация по типу,
  переход на ближайший кадр того же раунда, пауза и отображение исходного тика/кадра.
  Старые отчёты открываются с предложением повторить анализ для появления эпизодов.
- Устранены зависимость nav-пути от рабочей папки, неверная проверка локального
  tick_df через globals, зависимость этажа Nuke от ранее просмотренного будущего
  кадра, ошибки полного ESLint и выход карты за ширину страницы на телефоне.

## Подтверждение

Полный backend-набор: **376 тестов, 0 падений, 0 пропусков**, настоящая PostgreSQL 17
в отдельном локальном кластере. Рабочие базы не использовались. Сборка React и полный
ESLint проходят. Проверка выбора кадра покрывает границы раундов, отсутствующие
кадры и неверный тик. Новые backend-сценарии покрывают ложные срабатывания, дым,
неполные окна, одновременные события, безопасную проекцию JSON и отсутствие утечки
внутреннего контекста.

Chrome: все три вида на синтетических fixtures, факты/ограничения, фильтры, переходы
по раундам, пауза при выборе, JSON download, reload, ширина 390 px без прокрутки всей
страницы по горизонтали; два перехода по настоящим эпизодам. Ошибок JavaScript нет.
Большая карта сохраняет собственную горизонтальную прокрутку на узком экране.

## Требования и оставшиеся ограничения

Подробные 13 требований исходной заявки перечислены в итоговом DOCX.
Ранее составленный `docs/ivr-technical-audit.md` является историческим аудитом
изолированной PostgreSQL-ветки; текущие изменения описаны здесь.

№9 и №10 остаются частичными относительно обещания доказанных игровых проблем:
реализованы три типа кандидатов и их приоритизация, но не автоматическое доказательство
неверного решения. №11 реализован для кандидатов и проверен в браузере. Это ограничение
не скрыто за статистическими порогами и положительным исходом тестов.

Личные данные автора, группа, консультант, результаты опросов и ссылка на видео
не выдумывались. В документе они отмечены как требующие сведений автора.
Публичный deployment, полный redesign, FACEIT import и гостевой режим не добавлялись.
Инструкция запуска: `docs/ivr-runbook.md`.
